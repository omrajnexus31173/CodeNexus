### Development-only findings that remain

A full `npm audit --json` currently reports:

- 7 high: `@next/eslint-plugin-next`, `braces`, `chokidar`, `eslint-config-next`, `fast-glob`, `micromatch`, `tailwindcss`

The root advisories are:

- `braces <=3.0.3`: GHSA-vfj7-8cjw-p6xm, stack-exhaustion denial of service through deeply nested patterns. The installed version is already 3.0.3, and no later patched braces release was available in the registry check. npm's proposed removal path is a breaking Tailwind CSS 4 migration.
- `postcss-selector-parser <7.1.6`: GHSA-rj75-hqrm-r3gf, quadratic selector parsing. The installed Tailwind 3 toolchain uses 6.1.4; npm's proposed removal path is also Tailwind CSS 4.

Exposure assessment: these packages are used by lint/build tooling over trusted repository source during development/CI. They are excluded from the production runtime dependency tree, and untrusted learner code does not pass through Tailwind, ESLint, globbing, or CSS selector parsing. This is therefore tracked as a **build-toolchain residual**, not a production-runtime blocker under the requested `--omit=dev` criterion. The repository must not be described as having zero vulnerabilities across all dependency classes until a separately tested Tailwind 4/toolchain migration removes them.

## 4. Authentication and deployment hardening implemented

### Secrets and environment validation

- Removed runtime and script database credential fallbacks. A valid, non-placeholder `DATABASE_URL` is required.
- Production JWT configuration rejects missing, weak, and placeholder-classified secrets. Development may use an ephemeral in-process secret when no valid secret is configured; production may not.
- JWT signing and verification explicitly use HS256.
- New password hashes use bcrypt cost 12. Signup and reset require 12–72 UTF-8 bytes (the upper bound prevents silent bcrypt truncation); existing shorter passwords were not retroactively locked out at login.
- Script database access now goes through `scripts/lib/database-url.js`, which validates the URL and avoids TLS certificate bypass except for an explicit non-production `sslmode=no-verify` choice. The runtime rejects `sslmode=no-verify` in production.
- Seed users require operator-supplied `SEED_ADMIN_PASSWORD` and `SEED_STUDENT_PASSWORD`; no default password is embedded or logged.
- `.env.example` contains placeholders only. The real local `.env` is excluded from the ZIP.
- Error responses and logs were tightened so provider details, recipients, database URLs, and secrets are not returned to unauthenticated callers or written to logs.

### Authorization and account safety

- Admin stats and user-management routes now call a database-backed current-user check requiring `role='admin'` and `is_verified=true`; they no longer trust only stale JWT claims.
- Admin user updates validate the target ID, role whitelist, boolean verification value, and non-negative integer points; missing targets return 404.
- Career profiles are private to non-owners unless the stored profile explicitly has `is_public=true`; a missing profile row is not treated as public.
- Email verification and password-reset token protections remain enforced by the existing security suite: hashed/single-use reset handling, used-token rejection, expiry rejection, and concurrent-consumption protection all pass.
- Login continues to block unverified users server-side.
- The login page demo-account autofill helper was removed.

### HTTP, cookie, CSRF, and proxy handling

- Production auth cookie behavior was directly verified over HTTP locally: `HttpOnly`, `Secure`, `SameSite=Lax`, and `Path=/`. Chromium also confirmed the cookie is not readable through `document.cookie` and that no token-like item was in `localStorage`.
- Baseline response headers now include `X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`, a restrictive `Permissions-Policy`, COOP/CORP headers, production HSTS, and `Cache-Control: no-store` for auth APIs.
- API middleware rejects unsafe browser requests with cross-site `Sec-Fetch-Site`, a mismatched `Origin`, or an invalid `Origin`. Non-browser clients without browser headers remain supported.
- Forwarded client IP/host headers are trusted only when `TRUST_PROXY_HEADERS=true`. A spoofed `X-Forwarded-Host` test with proxy trust off returned 403.
- Application URLs used in email/certificate flows now come from the central environment helper rather than scattered localhost fallbacks.
- `/api/download-project` returns 404 in production unless `ALLOW_SOURCE_DOWNLOAD=true`. It no longer falls back to a machine-specific workspace path. The stale `public/code-nexus-production.zip` was removed, and both the API and static path now return 404 locally in production mode.

### Email

- Resend remains HTTPS-API only; no SMTP/Nodemailer fallback was introduced.
- Production rejects missing/placeholder/non-`re_` Resend keys, an unconfigured sender, the Resend test sender, and enabling the test mock.
- Provider/network failures return generic errors.
- **Live email delivery was not tested** because no Resend key or verified sender domain exists in this environment. The passing security suite tests graceful provider handling/token non-leakage, not mailbox delivery.

### Code execution

- `/api/execute` now enforces a 1 MB request cap, 64 KB code cap, 64 KB per test/input field, at most 20 test cases, 256 KB combined test payload, type validation, and a bounded execution queue (4 concurrent, 20 queued, then HTTP 429).
- Local untrusted execution fails closed unless both Bubblewrap and `prlimit` are available.
- The external execution adapter requires HTTPS and an API key in production (except loopback), validates the URL, applies an abort timeout, truncates output, and returns generic provider errors.
- The deep sandbox suite still passes filesystem isolation, network isolation, fork/process containment, output truncation, timeout, concurrent execution, and multi-language checks.

## 7. Remaining blockers and residual risks

1. **Live production email is untested.** Configure a real Resend API key and verified sender domain, then seat-test signup verification, resend verification, password reset, spam-folder behavior, and certificate URLs on the production domain.
2. **Stateless JWT revocation is incomplete.** Existing tokens are not globally revoked immediately after password reset or every account state change. Admin routes now recheck the database, but a future production hardening step should add a token-version/session-store design and regression tests.
3. **Development dependency audit is not zero.** The 9 findings above require a separately controlled Tailwind/toolchain migration or an upstream patched `braces` release. Production runtime audit is zero.
4. **Target-domain HTTPS/deployment was not tested.** HSTS and Secure cookies are configured for production, but DNS, TLS termination, proxy headers, canonical app URL, and cookie behavior must be verified on the actual host.
5. **No strict Content Security Policy is enabled yet.** Baseline browser headers are present, but a CSP compatible with Next/Monaco should be designed and browser-tested before being enforced.
6. **Sandbox hosting is specialized.** Production requires Linux with Bubblewrap, `prlimit`, Node 20, GCC/G++, Python 3, SQLite, and a compatible OpenJDK (this rerun used OpenJDK 11), or a properly configured external execution service.
7. **Generated questions remain quarantined.** Duplicate/title/topic review is unresolved; all 17,991 generated rows remain unassigned and exam-ineligible.
8. **Database provenance is reconstructed, not restored.** Production deployment must provision and seed PostgreSQL using the documented sequence or restore an operator-owned production backup.

## 8. Required production configuration checklist

At minimum, operators must set real values for:

- `DATABASE_URL` with verified TLS where the provider requires it
- `JWT_SECRET` (strong, unique, at least 32 characters; do not reuse a development value)
- `NEXT_PUBLIC_APP_URL` / canonical app URL for the HTTPS production domain
- `RESEND_API_KEY` and a verified production sender
- `TRUST_PROXY_HEADERS=true` only behind a proxy that overwrites forwarded headers
- `ALLOW_SOURCE_DOWNLOAD` left unset/false unless deliberately publishing an archive from `public/`
- External sandbox URL/API key if local Bubblewrap execution is not available

Do not seed local demo accounts into a public production database.
