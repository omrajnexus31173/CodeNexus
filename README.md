# Code Nexus — The Complete Developer Learning & Career Platform

**Code Nexus** is an enterprise-grade learning management system, code execution sandbox, examination proctoring engine, and automated career portfolio builder for mastering **C, C++, Python, SQL & PostgreSQL, Java, JavaScript, HTML & CSS, Mobile App Development (Kotlin & Flutter), Data Structures & Algorithms (DSA), and System Design**.

**Validation honesty (post-audit, Oct 2026):** 112 of 129 topics are `tested`. For 100 of them, every lesson example and assignment solution was executed in the bubblewrap sandbox and stdout byte-compared with the documented expected output (`scripts/validate-curriculum-examples.js --mark-tested`: **400/400 passed**, 3 nondeterministic examples accepted on successful execution only). The seeder also upserts all 28 course units before topics, so fresh installs get the expanded structure automatically. All Java examples are kept Java-11-compatible so they run on the sandbox JDK. Topic completion progress tracking awards **+50 Points** on course completion.

### 3. Practice Arena & Strict Scoring Engine
- **Question Bank (audited)**: **18,191 questions** — 18,000 preserved originals, **79 execution-validated topic-linked questions**, and **112 schema-v2 verified-core questions**. Statuses are honest: **200 `tested`** (9 hand-written curated + 79 topic-linked + 112 verified-core), **17,991 `generated`**, 0 `reviewed`. The curriculum-129 v2 architecture maps only the 200 tested rows to exact topics in their own courses; all 17,991 legacy generated rows remain `topic_id=NULL`, `mapping_status='unassigned'`, practice-only, and exam-ineligible because duplicate/title-domain review is still unresolved. Their independently computed outputs now match for 17,991/17,991 rows, the current stratified sandbox sample is 36/36 behaviorally consistent, and the 186 repaired SQLite `phrases` contracts pass individually (186/186), but **none of that promotes a generated row**. A separate final DB verifier also freshly executed every tested row’s stored reference and starter (200/200 references `Accepted`, 200/200 starters `Wrong Answer`). See `docs/QUESTION_BANK_REPORT.md` and `docs/FINAL_QUESTION_BANK_VERIFICATION.md`. Practice supports filtering by language, difficulty, Beginner/Intermediate/Advanced progression, exact lesson topic, and execution-tested status; lesson pages recommend only tested questions mapped to that exact topic. Hints and difficulty rationale stay hidden until the learner is permitted to see them.

- **Scoring Rules (Preserved Exactly)**:
  - **+4 Points**: For each correctly solved practice challenge.
  - **-1 Point per hint**: Up to 2 hints per question.
  - **0 Points**: If user reveals the solution via "Reveal Solution" without solving it.
  - **+50 Points**: Qualifying course completion.
  - **+10 Points**: Passing certification exam (> 85% score).
  - **0 Points**: Failed exam.
  - **-150 Points**: Unlocks any premium book, notes, or cheatsheet in the **Resource Library**.
  - **Auditable Ledger**: Every point earned or deducted is recorded in the PostgreSQL `point_ledger` table with anti-farming controls.

### 4. Fullscreen Proctored Examination & Verifiable Certificates
- **Session Duration**: 2-Hour countdown timer with automated submission.
- **Server-issued sessions**: `POST /api/exam/start` (login required) draws questions only from the exam's own supported course where the row is `validation_status='tested'`, `is_exam_eligible=true`, `mapping_status='mapped'`, not practice-only, linked to a real topic in that same course, and has at least three tests. It requires an approved pool of at least 25 and returns 409 with the actual pool size instead of substituting generated or other-course questions. C, C++, Python, Java, JavaScript, SQL, DSA, and System Design each currently have exactly **25 approved tested questions**. HTML/CSS and App Development intentionally have no graded exam because no deterministic rendering grader or Dart/Flutter sandbox runtime is integrated. `POST /api/exam/submit` revalidates the same pool rules, trusts only the server session, execution-grades answers in the sandbox, and rejects cross-user/duplicate/expired submissions.
- **Proctoring Restrictions**: Full-screen mode monitoring with violation counters (exiting full-screen or switching tabs generates security violation alerts).
- **Passing Threshold**: Strictly **more than 85%** required.
- **Certificate Issuance**: Official certificate generated with a unique cryptographically verifiable ID (e.g., `CN-CERT-2026-XXXX-XXXX`), score percentage, issue date, and public verification URL (`/verify-certificate?id=...`).

## 🛠️ Quick Start & Running Code Nexus

### 1. Verify PostgreSQL Database
```bash
npm ci
cp .env.example .env  # replace every placeholder with local-only values
npm run db:bootstrap:content  # schema + courses/curriculum/base questions/library; no user seeding
npm run verify:db
```

For a fresh database, `npm run db:bootstrap:content` runs the ordered base sequence—`init-db.js` → course seeding → education migration/seeding → learning-integrity, question-architecture, and auth-security migrations → base question/library seeding—and verifies the result. It never seeds users. Build and start the app, restore topic execution statuses with `node scripts/validate-curriculum-examples.js --mark-tested` and `node scripts/validate-sql-examples.js --mark-tested`, then build the verified question core only in evidence order: run `node scripts/validate-topic-linked-questions.js`, `node scripts/audit-curated-starters.js`, and `node scripts/validate-verified-core.js`; seed topic-linked and verified-core rows; run `node scripts/apply-question-architecture.js`; run the separate `node scripts/approve-verified-core.js` gate; finally run `node scripts/verify-final-question-bank.js`. The complete maintained sequence for reconstructing the quarantined legacy cohort and the 18,191-row state is in `DEPLOYMENT.md` section 4.3; never bulk-promote generated rows.

### 2. Run Test Suites
```bash
npm test                 # 16 feature/business-logic + 20 security tests
npm run test:curriculum  # 46 educational-engine schema/coverage/preservation checks
npm run test:expansion   # 29 expansion integrity checks (129 topics, 18,191 questions)
npm run test:examples    # executes every runnable lesson example in the sandbox (400 checks; --mark-tested promotes)
npm run test:sql         # executes SQL lesson queries against PostgreSQL fixtures (58 checks)
npm run test:sandbox     # 7 deep sandbox isolation boundary tests
npm run test:topic-questions   # executes all 79 topic-linked references + starters in the sandbox
npm run test:topic-duplicates  # mapping/duplicate checks for the 79
node scripts/validate-verified-core.js  # sequentially executes all 112 verified-core references + starters
node scripts/validate-sql-string-contracts.js  # executes the repaired SQLite string-contract cohort present in the target DB (186 in preserved 2026-10-20 evidence)
npm run audit:starters   # execution-audits curated starters/references for solution leaks
npm run test:integrity   # 61 learner API tests: auth, quiz, progress, hints, recommendations, approved exam pools
npm run audit:generated  # all 17,991 generated rows deterministically + current stratified sandbox sample (36 rows in the 2026-10-20 run)
node scripts/verify-final-question-bank.js  # DB counts + strict pools + fresh reference/starter execution for all 200 tested rows
npm run verify:db        # 6 core DB checks; add -- --require-exam-bank for 7 incl. strict pools
npm run verify:questions # structural bank audit incl. non-tested exam eligibility = 0
npm run migrate:integrity  # idempotent quiz-attempt/exam-session migration (safe to re-run)
npm run report:coverage  # regenerates docs/TOPIC_COVERAGE_REPORT.md
```

### 3. Start Development Server
```bash
npm run dev
```
The application binds to port 3000 and is immediately accessible.

## ⚠️ Production Notes (read before deploying)

This codebase passes its local functional/security suites, but that is **not** a claim that a real public deployment has been tested. The 2026-10-20 security remediation migrated the app to **Next.js 15.5.28**, retained React 18.3.1, and uses reviewed overrides for PostCSS 8.5.31 and Monaco's DOMPurify 3.4.17. After a clean `npm ci`, `npm audit --omit=dev --json` exits 0 with **0 production vulnerabilities**. The dated 2026-10-20 full audit reported 9 development-toolchain findings (7 high, 2 moderate). A fresh 2026-10-23 recovery audit reported a different advisory snapshot—3 moderate development-only findings in the Tailwind/PostCSS selector-parser chain—and the breaking Tailwind 4 fix was not forced; see `docs/SECURITY_REMEDIATION_REPORT.md` for the 2026-10-20 before/after record and `docs/REPOSITORY_RECOVERY_AUDIT_2026-10-23.md` for the recovery run.

Follow `DEPLOYMENT.md` for the VM, Render, and Netlify paths; run `npm run check:production -- --ping` before launch and `npm run smoke -- https://<your-domain>` after launch. Before real deployment you must still: configure a real Resend API key + verified sender domain and test live mailbox delivery (signup cannot be completed without it); set a unique strong `JWT_SECRET` of at least 32 characters; set the canonical HTTPS app URL and run behind correctly configured TLS/proxy headers; provide Bubblewrap/`prlimit`-capable Linux hosting (or wire the external sandbox adapter) — user code must never run in the Next.js process; install Node 20, GCC/G++, a compatible OpenJDK (the local gate used 11), Python 3, and SQLite; provision PostgreSQL and apply the documented migration/seed sequence; never seed local demo accounts into production; design immediate stateless-JWT revocation if your threat model requires it; and smoke-test email verification, password reset, cookies, and certificate verification end-to-end on the target domain. The production source-download API is disabled unless `ALLOW_SOURCE_DOWNLOAD=true`, and no source ZIP is shipped under `public/`.

Known content limits remain: 17 lesson topics are `reviewed` (not execution-tested); 17,991 generated questions remain unverified as complete curriculum-mapped questions and are quarantined from exams; the eight supported exam courses have 25 approved tested questions each; and HTML/CSS and App Development have no graded exam until deterministic graders/runtimes exist (see `docs/QUESTION_BANK_REPORT.md`). The local database used for the 2026-10-20 rerun was reconstructed from preserved scripts after a sandbox reset; the source ZIP is not a database backup.
